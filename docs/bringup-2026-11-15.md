## 1. GPU：从 panfrost probe -110 到 Wayland 桌面

### 1.1 内核侧：MFG MTCMOS 时钟没编进去

mali 节点的七个 `mtcmos_mfg*` 时钟由 `clk-mt6893-pg.c` 提供
（`compatible = "mediatek,mt6893-scpsys-clk"`），但 `chopin_defconfig` 从来没打开
`CONFIG_COMMON_CLK_MT6893_PG`。

结果：panfrost 对每个时钟 `devm_clk_get_optional` 都拿到 `-EPROBE_DEFER`（打印 `-517`），
却继续用 NULL 时钟初始化 → MFG0..MFG6 电源域从未打开 → GPU 寄存器读回 0
（`using only 1st core group (0 cores from 0)`）→ 软/硬复位永远超时 → probe -110、没有 `renderD128`。

顺带还有一个次要 bug：mfgcfg 门控的父时钟名写成了 mt8192 的 `mfg_pll_sel`，MT6893 应该是
`mfg_sel`，导致 `bus_clock rate = 0`。

修复（补丁 0021）后启动日志：

```
[    0.7] MTCMOS clocks: 7 real (MFG), 33 placeholders
[    2.79] panfrost 13000000.mali: mali-g77 id 0x9080 major 0x0 minor 0x1 status 0x1
[    2.79] panfrost 13000000.mali: shader_present=0x660067 l2_present=0x1
[    2.79] panfrost 13000000.mali: clock rate = 349999848
[    2.79] panfrost 13000000.mali: bus_clock rate = 349999848
[    2.80] [drm] Initialized panfrost 1.6.0 for 13000000.mali on minor 0
```

### 1.2 用户态：Mesa 不认识 G77

Debian 的 Mesa 25.0.7 的 panfrost 型号表里没有 product id **0x9080**（MT6893 的 Mali-G77），
`panfrost_get_model()` 返回 NULL，DRI 驱动直接放弃 → 整个 GL 栈回落到 llvmpipe。

修复来自参考项目 [MT6891-Mainline/mesa](https://github.com/MT6891-Mainline/mesa) 的
`panfrost: add the Mali-G77` 提交，只加一行：

```c
MODEL(0x9080, 0, "G77", "TTRx", HAS_ANISO, 16384, {}),
```

然后交叉编译出 `libgallium-25.0.7-2+deb13u1.so`（`-Dgallium-drivers=panfrost -Dplatforms=x11`，
版本号必须和 Debian 包一致，否则 `libEGL_mesa` 的 `DT_NEEDED` 对不上）。
这份构建**只有 panfrost，没有 llvmpipe**；需要软件渲染时用 `MESA_INSTALL_G77=0` 回退。

### 1.3 显示与渲染的配对：kmsro

chopin 有两个 DRM 设备：

- `card1` = `mediatek-drm`（显示控制器，KMS）；
- `card0` / `renderD128` = `panfrost`（纯渲染，没有显示输出）。

Mesa 的 **kmsro**（kernel modesetting render-only）就是为这种「显示卡 + 渲染卡」组合准备的：
它用 `pipe_loader_get_compatible_render_capable_device_fds()` 在 platform bus 上找到 panfrost
渲染节点，把两者配成一对。前提是**合成器/服务器以显示卡为 KMS 设备启动**。

### 1.4 X11 能建上下文，但 mutter 不出帧

X11 路线（modesetting + glamor）实测：

- `Xorg.0.log`：`glamor X acceleration enabled on Mali-G77 (Panfrost)`；
- `glxinfo -B`：direct rendering yes、Accelerated yes；
- `glxgears`：122 FPS。

但 **gnome-shell 停在启动画面**：0% CPU、D-Bus 不回话、之后起的窗口不会出现在屏幕上
（截屏前后字节完全相同）。原因指向 Xorg 把 GLX 初始化成 **DRI2** provider
（`GLX: Initialized DRI2 GL provider`），Mesa 25 的 DRI2 客户端路径早已不维护，
mutter 等 swap 完成事件永远等不到。

结论：**桌面走 Wayland**。`WaylandEnable=true` 后 gnome-shell 作为 wayland 合成器运行，
EGL/GBM 直接开在 `card1` 上、kmsro 配 panfrost，桌面正常。

### 1.5 证据

| 检查 | 结果 |
| --- | --- |
| `eglinfo -B` | GBM / Surfaceless / Device / X11 四个 platform 都是 `Mali-G77 (Panfrost)` |
| `glxinfo -B` | direct rendering yes、Accelerated yes、GL 3.1 / GLES 3.1 |
| `glxgears` | 614 frames / 5.0 s = **122.7 FPS**（vsync 120 Hz） |
| 会话 | `loginctl show-session <id> -p Type` = `wayland` |

## 2. 触摸：从 IRQ 不触发到 24 点校验

### 2.1 根因一：host-download 型触摸 IC 缺固件

NVT36672C 是 **host-download** 芯片：冷启动后芯片里没有可用固件，原厂内核每次启动都会把
`novatek_nt36672c_k10a_fw01.bin` 通过 SPI 下载进去。

主线 `linux-firmware` 没有这个文件，于是：驱动 probe 成功、input 设备注册、IRQ 33 注册，
但芯片不扫描、INT 线永不触发（IRQ 计数恒 0）——看起来像"中断配置错"，其实是缺固件。

固件在设备自己的 **vendor 逻辑分区**（物理 `super` 分区内）。做法：

1. 用 liblp 解析 `super` 的元数据（`scripts/lp.py`）；
2. `losetup -r --offset ...` 只读挂载 vendor 分区；
3. 把 `/firmware/novatek_nt36672c_k10a_*.bin` 复制到 `/lib/firmware`；
4. 固化成一个幂等的 systemd 服务（`chopin-nvt-firmware.service`），首启自动完成。

### 2.2 根因二：lockdown 读取时序

新内核上触摸驱动在 mi-dsi panel 之前 probe，`get_lockdown_info_for_nvt()` 读到全 0，
10 秒后 `nvt_match_fw()` 看到全 0 的 lockdown，选错默认固件（请求不存在的 fw02）。

修复（补丁 0024）：每 500 ms 重试读 panel lockdown，最多 20 s，读到有效值再锁定。
实测启动 16 s 时打印 `match panle type, fw is [novatek_nt36672c_k10a_fw01.bin]`，
`Update firmware success!`，IRQ 33 正常计数。

### 2.3 根因三：移植时臆造的「右半屏 Y 翻转」

驱动里有这么一段（移植补丁 0008 带进来的）：

```c
/* This panel reports the right half with the opposite
 * Y direction; only flip that half. */
if (nvt_invert_y && input_x >= (ts->abs_x_max / 2))
        input_y = ts->abs_y_max - input_y;
```

`nvt_invert_y` 来自 DTS 属性 `novatek,invert-y`。对照原厂内核
（`Xiaomi_Kernel_OpenSource-chopin-r-oss.zip`）：

- `drivers/input/touchscreen/NVT36672c/nt36xxx.c` **没有任何 invert / 镜像逻辑**；
- `arch/arm64/boot/dts/mediatek/novatek-nt36xxx-spi.dtsi` **没有**这个属性。

所以这是移植时凭现象加的猜测，效果是 **x ≥ 540 的所有触摸 Y 被镜像**。删掉属性和代码
（补丁 0025）后正常。

### 2.4 验证数据

修好后让用户按「上左 → 上中 → 上右 → 下一行」点了 3 列 × 8 行 = 24 次，evtest 上报：

| 列 | y 序列 |
| --- | --- |
| 左 x≈70–110 | 1634 → 1413 → 1179 → 881 → 638 → 363 → 114 → 40 |
| 中 x≈480–570 | 1580 → 1387 → 1085 → 844 → 586 → 336 → 198 → 49 |
| 右 x≈990–1050 | 1837 → 1600 → 1386 → 1074 → 772 → 551 → 340 → 231 → 39 |

三列各自单调、没有镜像跳变（镜像时右上的点击会上报成 y≈2337）。再点右上角电池图标，
快捷设置面板从右上角弹出——位置确认正确。

## 3. 稳定性：SError 与内存布局

### 3.1 现象

```
SError Interrupt on CPU7, code 0x00000000be000411 -- SError
pc : clear_page+0x34/0x6c
lr : get_page_from_freelist+0x17bc/0x19e8
```

异步外部中止，栈在「首次触碰新分配页」或 ext4 写路径。旧内核在 X11 桌面下 1–3 分钟必崩。

### 3.2 根因方向：reserved-memory 与 LK 不符

板级 DTS 的 mblock 表是从别的机型抄的，而真实布局由 LK 在启动时写进 `memory/mblock_info`；
内核又用内嵌的 `chopin-board.dtb` 覆盖了 LK 的 FDT，于是漏掉的 carve-out 全变成"空闲 RAM"，
首次触碰就总线中止。

用补丁 0022 的 `CHOPIN-LKDT:` dump 拿到真值后，0023 修正了 6 个节点（本机是 6 GiB 版本）：

| 节点 | 旧值 | LK 真值 |
| --- | --- | --- |
| mblock-24-md_mem_usage | 0xe0000000 | 0xde000000 |
| mblock-25-md_mem_usage | 0xe3000000 | 0xe1000000 |
| mblock-26-md_mem_usage | 0xe4000000 | 0xe2000000 |
| mblock-27-md_mem_usage | 0xfa850000 | 0xf8850000 |
| mblock-29-ap_md_c_smem | 0x6e000000 | 0x70000000 |
| mblock-30-adsp | 0x6c000000 | 0x6e000000 |
| mblock-1/2-dramc-rk0/1 | 0x01_3ffff000 / 0x02_3ffff000 | 0xfffff000 / 0x1bffff000 |

### 3.3 长稳数据

修正后：Wayland 桌面连续 **3 小时 32 分**无 SError，其中 40 分钟跑 dd 读写（96 MB 循环 fsync）+
160 MB bytearray 反复分配 + glxgears；之后 2 小时空闲。内核日志从 327 s 起无任何输出，
`dmesg` 里 SError / UFS 错误计数都是 0。

### 3.4 仍未根除

mblock-26（结束于 `0xe9b10000`）与 mblock-27（起始于 `0xf8850000`）之间还有 **237.25 MiB**
不在 LK 的 mblock 表里。补丁 0025 把它按 `no-map` 保留作为对照实验（代价 237 MiB 可用内存），
镜像已构建、还没长期验证。

## 4. 刷机：两个必须知道的坑

### 4.1 boot.img 的 dtb 段必须保留原厂 blob

第一次打包时用 `--dtb mt6893-xiaomi-chopin.dtb`（构建产物 280,640 B）替换了 dtb 段，
刷入后设备在 LK 阶段**反复重启**；不传 `--dtb`、保留模板里原厂的 **201,848 B** 段后正常启动。

原因：运行时设备树来自内核内嵌的 `chopin-board.dtb`，boot.img 的 dtb 段只影响 LK；
把一棵完整的大 DT 塞给 LK 会出问题。**打包时只换 kernel（和 ramdisk），不要动 dtb 段。**

### 4.2 release 字符串必须和已装模块一致

只替换 Image.gz 时，如果内核 release 变了（比如从 `7.3.4-g5775fb2ac0a1-dirty` 变成
`7.3.4-g676614a32…`），`/lib/modules/<release>` 对不上、模块 vermagic 不匹配，
panfrost 等模块全部不加载，桌面起不来。

补丁 0025 给 `scripts/setlocalversion` 加了钩子：

```sh
if test -n "$CHOPIN_LOCALVERSION"; then
        echo "${KERNELVERSION}$CHOPIN_LOCALVERSION"
        exit 0
fi
```

构建时 `CHOPIN_LOCALVERSION='-g5775fb2ac0a1-dirty'` 即可钉住 release。
注意必须带上 `${KERNELVERSION}` 前缀——这个内核的 Makefile 直接拿脚本输出当整个 release，
只输出后缀会得到 `-g5775fb2ac0a1-dirty` 这种错误版本号（我们踩过）。

### 4.3 完整流程

```bash
# 内核
CHOPIN_LOCALVERSION='-g<old-release-suffix>' make ARCH=arm64 CROSS_COMPILE=aarch64-linux-gnu- \
    -j16 Image.gz dtbs

# 打包（原厂 boot_a.img 作模板，保留其 dtb 段）
python3 scripts/mkbootimg.py --stock stock/boot_a.img \
    --kernel linux/arch/arm64/boot/Image.gz -o out/boot-chopin-touch.img

# 刷入（手机关机后音量减 + 电源进 fastboot）
fastboot flash boot out/boot-chopin-touch.img
fastboot reboot
```

## 7. 2026-11-15 下午：USB 网络 / WiFi / 音频（详见 debian 仓库 BRINGUP §14–19）

### 7.1 USB 网络：CDC-NCM + SSH

- RNDIS 功能本身能起来，但这台 Windows 11（build 26300）**没有绑定驱动**（Problem 28：
  没有 `rndismpx.sys`，`netrndis.inf` 只匹配需要 MS OS 描述符的 `ms_rndisusb`）；
- 改用 **CDC-NCM**：Windows 自带的 `usbncm.inf` 匹配 `USB\Class_02&SubClass_0d&Prot_00`，
  正好是 Linux `f_ncm` 控制接口的类/子类/协议 → 自动加载 `UsbNcm Host Device`；
- 设备端 `usb0 = 192.168.42.2/24` + dnsmasq，Windows 自动 DHCP；**SSH 免密可用**；
- 坑：configfs 不能用 `rm -rf` 拆 gadget（属性文件不可 unlink），必须
  unbind → 删 configs 软链 → `rmdir` 各 function → `rmdir` gadget。

### 7.2 WiFi：WLAN-GEN4 + 固件/NVRAM

- `wlan0` 一直不出现，根因是三样二进制缺失：
  1. NVRAM：nvdata 分区 `/APCFG/APRDEB/WIFI`（6146 B，每台机器的出厂校准）；
  2. SoC 固件：vendor 逻辑分区 `WIFI_RAM_CODE_soc3_0_1a_1.bin` + `soc3_0_ram_*.bin`
     （缺 `wmmcu` header 时直接 `WiFi on/off op fail`）；
  3. 用户态：`wpasupplicant` / `iw` / `wireless-regdb` 没装（装完还要重启 NetworkManager）。
- 新增 `chopin-wifi-firmware.service`（`Before=sysinit.target`）在驱动放弃前把文件装进
  `/lib/firmware`；实机 wlan0 连上 5 GHz（5240 MHz、780 Mbit/s），apt 实测 1.8 MB/s。

### 7.3 时间：RTC 没有电池

- 系统时间停在 2026-04-14，所有 HTTPS 因证书"尚未生效"失败（apt 源全是 https）；
- 手动校准后装 `systemd-timesyncd`，现在 `System clock synchronized: yes`。

### 7.4 音频：扬声器出声

- `sound/soc/mediatek/mt8192/mt6893-mt6359.c` 一直在树里，但
  `CONFIG_SND_SOC_MT6893_MT6359` 从未打开；补丁 0026 打开它，并导出 AFE 的
  `mt8192_mck_enable/disable`（machine driver 作为模块引用）；
- 实机：`card 0 [mt6893mt6359]`，两颗 CS35L41（i2c6 0x40/0x42）probe 成功，
  `speaker-test` 外放有声；
- 用户态：PipeWire 需要 `dbus-user-session`；系统音量必须走**软件音量**
  （`api.alsa.soft-mixer=true`），否则音量条只是"装饰"。
