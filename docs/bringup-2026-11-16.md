# chopin bring-up 记录 — 2026-11-16（CPU 提频、崩溃取证、充电与体验修复）

> 设备：Redmi Note 10 Pro 5G / POCO X3 GT（chopin，MT6891Z/CZA）
> 内核：Linux 7.3.4 + 34 个补丁；用户空间：Debian 13.7 + GNOME 48.7（Wayland，Mesa 25.0.7 G77）
> 这一轮全部在实机上验证过；前一天的记录见 [bringup-2026-11-15.md](bringup-2026-11-15.md)。

## 0. 一句话

这一轮把「卡顿」定位到 **A78 集群被 bootloader 钉在 729 MHz**（2.6 GHz 的 28%），并用一个
轻量驱动 + 用户态服务把它拉到 **1.5 GHz（×2.05）**；同时把一批随机崩溃追到 **显示 DMA mask
只有 32 位**（>4 GiB 的 scanout buffer 全走 SWIOTLB，而 SWIOTLB 单次上限 256 KiB，必然失败），
修好后每启动 50–114 次的映射失败归零；顺带修掉外放偏小、充电停在 89%、Wi-Fi 面板多网卡、
电源键不锁屏等问题。

## 1. 卡顿：A78 只有 729 MHz

用依赖链基准（每次迭代 16 条串行 add，1 周期/条）钉核实测：

    cpu0/cpu2 = 1.780 / 1.778 GHz   (A55, armpll_ll)
    cpu4/cpu6 = 0.729 / 0.728 GHz   (A78, armpll_bl)   ← 厂商 OPP 表是 2.6 GHz … 659 MHz

原因不是配置漏项：MT6893 的 CPU DVFS 由 **MCUPM 固件 + MCUSYS CSRAM（0x0011bc00）表**
驱动，CPU 电压在 **MT6315（SPMI）** 上，而本移植没有 SPMI 驱动；mainline 的
mediatek-cpufreq-hw 是 MT8183/8195 的 LUT 接口，MT6893 的 DT 只有一个空的
mediatek,mt-cpufreq 节点。所以内核从来没碰过 CPU 频率。

### 解决办法（方案 A）

* 新驱动 chopin-cpuclk（misc）：通过 DT 节点 chopin,cpuclk 拿到 armpll_bl0..3 / armpll_ll，
  暴露 bl_freq / ll_freq；**写之前强制要求 cpu4..7 全部 offline**——带锁 PLL 重锁会把
  MCUSYS AXI 卡死（GPU 提频那次已经验证过这个坑）；
* 用户态 chopin-cpu-freq.service：modprobe → offline 大核 → 写 1.5 GHz → online，开机执行；
* 结果：cpu4..7 = 1497–1498 MHz，45 秒全核 + 内存压测 0 SError / 0 UFS 错误，电池 35.8 °C；
* 限制：PLL fmin 是 1.5 GHz（没有更低档）；1.8 GHz 未试（电压不可控，风险自负）。

## 2. 随机崩溃：SWIOTLB 的 256 KiB 上限

Chrome 的 GPU 进程和 Nautilus 交替被杀，日志是 Wayland Error 71 / Mojo 断开。
现场有两层证据：

1. panfrost 作业故障：Unhandled Page fault in AS0 at VA 0x0（JOB_BUS_FAULT），随后 GPU 卡死；
2. 同一时刻 mediatek-drm 反复报 swiotlb buffer is full（每启动 50–114 次）。

把 swiotlb 从 2 MB 提到 64 MB **完全没用**：kernel/dma/swiotlb.c 第一道检查就是
alloc_size > IO_TLB_SEGSIZE * IO_TLB_SIZE（128 × 2048 = **256 KiB**）直接失败，
而显示驱动请求的是 512 KiB–14 MiB。

根因是显示设备的 DMA mask 被钉在 32 位（mtk_drm_crtc.c 显式设 coherent mask 32 位，
而 mtk_drm_drv.c 里那处 34 位被 if (dma-ranges) 包着，本 DTS 没有该属性）：5 GiB 内存里
4 GiB 以上的 buffer 全都要 bounce，而 bounce 又不可能成功 → 合成器把坏 buffer 交给客户端，
mutter 以协议错误杀掉客户端。

修复：显示 DMA mask 32 → **34 位**（显示引擎本身就支持，mtk_disp_ovl.c 一直是 34 位）。
验证：swiotlb buffer is full 从 114 → **0**，panfrost fault 0，Chrome 不再崩。

## 3. 充电与电量显示：4.35 V 的锅

电量计按电池设计上限 **4.46 V** 算 100%，而驱动复位值只充到 **4.35 V** → 永远显示 89%；
再加上 900 mA 输入时进电池只有 ~300 mA，很容易掉到终止电流（最小 100 mA）以下提前 EOC，
而 MT6360 驱动不会自动重启充电，状态就锁死在 Full。

修复：截止电压 4.4 V、终止电流 100 mA、输入 900 mA、充电 1.5 A，另加 chopin-charge-recharge.timer
（每 5 分钟检查，Full 且 <99% 时把输入限流 0 → 900 mA 循环一次清掉锁存）。
实测：电池电流 −8 mA → +296 mA，电压从 4.333 V 继续上升。

## 5. 已知问题（未解决）

* **Nautilus 重命名必崩**：在重命名对话框里按屏幕键盘任意键 → Wayland 协议错误。
  这是 Debian bug #1151025（gnome-shell 48.7 + gtk 4.18.6 + nautilus 48.3-2，在另一台
  ARM 触摸屏设备上同样 100% 复现），属上游问题，暂不处理；
* **CPU 电压不可控**：MT6315 在 SPMI 上，Linux 读不到也改不了，所以 1.5 GHz 以上没有安全
  依据；正统做法是移植 MCUPM + cpufreq；
* **USB host 不可用**：xhci 子节点缺 phys（USB0 root hub has no ports），且角色停在 peripheral；
* **蓝牙**：CONFIG_MTK_BTIF 未开，栈在树里但缺 DTS 节点与固件；
* 传感器（SCP）、相机、视频硬解、指纹仍未做；8 GiB 机型未验证。
