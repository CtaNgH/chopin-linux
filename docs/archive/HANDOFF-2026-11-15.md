## 1. 已验证（实机）

- 内核能启动到用户态；DRM `card0-DSI-1` connected，1080×2400，fbcon 正常。
- 触摸 `NVTCapacitiveTouchScreen`、按键 `mtk-pmic-keys` / `mtk-kpd` 正常。
- UFS 正常，userdata = `/dev/sdc75`。
- mtu3 UDC 能注册出 `11201000.usb`；configfs gadget 在该 UDC 上曾枚举成功过一次
  （Windows 侧 `VID_1D6B/PID_0104` + COM11）。

## 2. 未验证 / 待解决（内核侧）

1. **USB**：当前 DT 是 `dr_mode="otg"` + 默认 device 角色 + 无 `vbus-supply`（详见 docs-kernel.md 5.2）。
   这套组合下 gadget 能否稳定枚举**还没验证完**（最后一次刷机被中断）。
2. 内建 `g_multi` 的 `probe -EINVAL`（`drivers/usb/gadget/legacy/multi.c`）—— 修好可一次拿回
   ACM+RNDIS+存储。
3. i2c5 上 MT6360 子设备（`subpmic_pmic@1a` / `subpmic_ldo@64` / `tcpc`）注册失败，
   影响 charger 与 `otg_vbus`。
4. WLAN 缺 `mediatek/mt6893/WIFI`（在 nvdata 分区）；音频、相机未验证。
5. 显示栈是 vendor `mediatek_v2`（fbdev 级别，无 GBM/GL）。

## 3. 构建与刷写

```bash
cd /root/MT6891-Mainline
./scripts/build.sh                     # defconfig + Image.gz + dtbs + modules

# 打包 boot.img（以原厂镜像为模板，只换 kernel）
python3 scripts/mkbootimg.py \
  --stock /mnt/d/MT6891-Mainline/chopin/images/boot_a.img \
  --kernel linux/arch/arm64/boot/Image.gz \
  -o out/boot-chopin-mainline.img
```

Windows 侧刷写（`fastboot.exe` 是 **32 位**，>2 GB 镜像会 `std::bad_alloc`）：

```powershell
$pt = "D:\Program Files (x86)\platform-tools"
& "$pt\fastboot.exe" flash boot D:\MT6891-Mainline\out\boot-chopin-mainline.img
& "$pt\fastboot.exe" reboot
```

辅助脚本：`scripts/capture-serial.ps1`（抓 USB 串口，115200，DTR/RTS）、
`scripts/flash-when-ready.ps1`（等 fastboot 出现→刷→重启→抓串口）、`scripts/boot-cycle.ps1`。

## 5. 恢复原厂

```
fastboot flash boot D:\MT6891-Mainline\chopin\images\boot_a.img
fastboot flash dtbo D:\MT6891-Mainline\chopin\images\dtbo_a.img
```

slot 被切到 `_b` 时先 `fastboot --set-active=a`。原厂分区 dump 在 `chopin/images/`。
